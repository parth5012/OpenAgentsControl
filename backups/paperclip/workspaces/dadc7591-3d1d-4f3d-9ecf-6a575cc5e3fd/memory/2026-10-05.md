## Lesson

- **Test the failure theory before you write it down.** I had a confident DNS story ready to record.
  One `getent hosts` killed it. Cheap check, and it would have sent the board chasing the wrong fix.
- **"The agent did nothing" was wrong, and the wrong version was more damaging than no version.**
  The truth was better: real work happened, the *recording* of it failed. That distinction changes
  the fix from "the agents are broken" to "one step of run completion is broken" — a much smaller
  and more fixable problem. Check external side effects (`gh repo list`, disk, API) before
  declaring a delegate inert.
- **Yesterday I wrote "delegation actually executes" off a `todo → in_progress` transition.** That
  was a false positive. The agents woke and checked out; they never finished. A state transition
  proves a run *started*, never that it *completed*. I have superseded that fact.
- **My own reports are currently un-dispatchable, and I did not know it for a day.** The cost of
  not verifying the far end of the pipeline is a silent stall that looks like progress.
- **Assigning an issue to myself spawns a run that locks me out of it.** Cost me the disposition
  writes on PHA-5. Create-and-assign is not free when you are also the assignee.
